# PRD：A02 可解释处置与英雄场景真实尺度

> Status: Confirmed
> Pilot-ready: Yes
> Owner: FieldVision
> Updated: 2026-07-22

<!-- clarified: 2026-07-22 -->

## 1. Background

FieldVision 已经具备从基地总览进入 A02、无人机扫描、启动灌溉并返回恢复状态的完整五段演示，也已完成第一轮光照、作物、水渠、设施和镜头写实化。

下一阶段将两个已选改进包合并交付：

1. 让异常识别、灌溉处置和恢复验证成为观众可以在空间中看懂的证据链；
2. 让开场总览、A02 俯冲路径和英雄近景具备可信的江南/长三角现代稻作区尺度与环境细节。

本 PRD 是增量需求，不重述或重做现有五段演示、地块交互和图层系统。

## 2. Problem

当前 Demo 的流程已经完整，但仍存在两类说服力缺口：

- **业务可信度不足**：观众主要通过 UI 文案得知“缺水”“正在灌溉”“已经恢复”，三维场景没有充分展示判断依据、设备动作、水的到达顺序和复测证据。
- **环境可信度不足**：远景山体、树线和部分地表仍带有程序化重复感；缺少农用车辆、轮迹、水尺、供电与维护痕迹等现实尺度锚点，容易暴露 Demo 感。

## 3. Goals

1. 观众无需阅读大段面板文字，也能从三维动画理解“发现—判断—处置—验证”的因果关系。
2. A02 异常判断至少同时呈现空间范围、采集来源、采集时间和一个核心指标。
3. 灌溉过程清楚表达泵站、闸门、主渠、支渠和田间湿润锋的先后关系。
4. 恢复阶段用同机位视觉对比和复测结果证明风险解除，而不是只把颜色改回绿色。
5. 开场总览与 A02 英雄路径不再出现明显重复球冠、锥体树、塑料山体或缺乏尺度参照的大面积空地。
6. 保持“三维场景就是产品”，不把新增证据做成传统农业 Dashboard。

## 4. Functional Requirements

### 4.1 无人机扫描证据落地

- Actor: 现场观众、演示者
- Trigger: 自动演示或时间线进入“发现异常”章节
- Flow: 无人机进入 A02 后，扫描带沿航线推进；已扫描区域逐步显露长势/墒情结果；异常斑块边界在扫描经过后形成，而不是章节开始即完整出现。
- Success: 观众可以看到扫描覆盖顺序和异常区域如何被识别。
- Failure: 无人机资产或扫描效果不可用时，保留地面扫描带和异常结果，流程不得中断。

### 4.2 空间化采集元数据

- Actor: 现场观众
- Trigger: 异常斑块完成识别
- Flow: 在异常区旁显示一张小型空间标注，包含“演示模拟”、采集时间、来源“多光谱无人机”、墒情 18%、相对同品种长势 -12% 和置信度；标注随镜头自动避让，但不遮挡异常区。
- Success: 观众能回答“数据从哪里来、何时采集、为什么判定异常”。
- Failure: 小屏幕空间不足时，只保留“演示模拟”、时间、墒情和异常幅度四项。

### 4.3 异常原因假设

- Actor: 现场观众、演示者
- Trigger: 扫描完成后
- Flow: 以一句可验证的结论连接空间证据与供水设施：“A02 东侧连续低值，东支渠末端供水不足”；同时高亮 A02 东侧、东支渠末端和对应闸门。
- Success: 异常斑块和处置对象之间形成明确空间关系。
- Failure: 不展示不可验证的病虫害、土壤成分等额外结论。

### 4.4 设备启动顺序

- Actor: 演示者
- Trigger: 点击“启动灌溉演示”或自动流程进入“灌溉处置”
- Flow: 依次表现泵站启动、状态灯亮、闸门开启、主渠水位上涨、东支渠到水；每个关键节点出现短暂回执，前一步完成后才进入下一步。
- Success: 观众能够复述设备动作顺序，且设备状态与水流动画一致。
- Failure: 中途切换章节或重新播放时，取消旧动画并从目标章节的规范状态恢复，不出现状态灯、水位和 UI 相互矛盾。

### 4.5 分段水路反馈

- Actor: 现场观众
- Trigger: 主渠开始进水
- Flow: 水流沿真实渠道分段推进；渠边水尺或轻量空间标记反馈“主渠到水”“东支渠到水”“A02 进水口到水”；水面高度、速度和回执必须与灌溉进度一致。
- Success: 水不会凭空出现在 A02，观众能顺着渠道追踪水的来源。
- Failure: 低性能档可以减少粒子和水面细节，但不得改变到水顺序。

### 4.6 田间湿润锋与作物响应

- Actor: 现场观众
- Trigger: A02 进水口到水
- Flow: 湿润锋从渠口向异常区推进；地表湿润、浅水反光、作物颜色和墒情数字按同一空间前沿依次恢复，作物恢复略晚于地表到水。
- Success: 恢复是渐进、有方向且有时间差的过程。
- Failure: 不允许整块田瞬间变绿；性能降级时可以降低网格精度，不得退化为一次全局颜色切换。

### 4.7 恢复复测与同机位对比

- Actor: 现场观众、演示者
- Trigger: 灌溉进度完成
- Flow: 相机返回异常识别时的验证机位，短暂展示“处置前 / 复测后”擦拭或残影对比；显示复测时间、墒情 18% → 27%、异常面积收敛和“风险已解除”。
- Success: 观众能肉眼确认异常区变化，并看到复测证据。
- Failure: 小屏幕下改为自动擦拭，不要求用户拖动控件。

### 4.8 照片级稻作区远景

- Actor: 所有观众
- Trigger: 页面开场、基地总览、A02 近景朝向地平线
- Flow: 使用地域匹配、许可清晰的自制或 CC0 远景资产替换当前程序化山体和重复树线；至少形成近树带、中远村田层、远山/天际三个深度层，并与晨光、雾和地面色温一致。
- Success: 1440×900 总览和 A02 近景中不出现明显交叉树片、重复球冠/锥体或塑料山体轮廓。
- Failure: 资产加载失败时使用经过优化的本地备用远景，禁止依赖运行时外网。

### 4.9 生产痕迹与尺度锚点

- Actor: 所有观众
- Trigger: 开场总览和 A02 飞入路径
- Flow: 在不抢夺英雄地块注意力的前提下，布置农用车辆、远处作业人员、供电杆线、水尺、渠道编号、机耕路轮迹、泥水边缘和维护痕迹；位置应符合道路、泵站、渠道的使用逻辑。
- Success: 画面具备可感知的人体、车辆、设施和农田尺度，环境显得被长期使用和维护。
- Failure: 低性能档可以隐藏远处人员和次要小物，但保留关键尺度参照。

### 4.10 A02 英雄资产精修

- Actor: 所有观众
- Trigger: 进入 A02、异常扫描和灌溉处置镜头
- Flow: 精修 A02 渠口、闸门、涵洞、泵站可见面和近景稻株；补足结构连接、材质粗糙度差异、泥渍、水渍、锈蚀、边缘磨损和接地阴影。
- Success: 0–20 米镜头内没有明显悬浮、穿插、纯色几何体、低面数主轮廓或重复贴图。
- Failure: 若完整资产成本过高，只精修预设镜头实际可见面，但自由浏览不能看到空壳背面。

### 4.11 演示状态一致性

- Actor: 演示者
- Trigger: 自动播放、时间线跳转、重新播放、返回总览
- Flow: 每个章节定义可重复进入的规范状态，包括设备灯、闸门、水位、扫描覆盖、异常范围、湿润锋、作物状态和数据标注；跳转时先取消旧序列再应用新状态。
- Success: 连续跳转五个章节或重新播放三次，三维状态、UI 状态和数字保持一致。
- Failure: 任一子效果异常不得阻断相机与主流程控制。

## 5. Roles and Permissions

本 Demo 无登录和权限系统。

- **现场观众**：观看自动演示、读取空间证据、理解处置结果。
- **演示者**：播放完整演示、跳转章节、进入 A02、启动灌溉和返回总览。

## 6. Business Rules

1. 所有指标必须明确属于“演示模拟”，不得伪装成已接入的实时生产数据。
2. 数据只用于支撑 A02 缺水故事，不扩展为多地块告警或完整农业分析平台。
3. 异常证据、设备动作、渠道到水、湿润锋、作物恢复和复测数字必须使用同一进度模型，禁止各自独立计时导致状态矛盾。
4. A02 初始墒情保持 18%，目标保持 27%；长势相对同品种平均值保持 -12%，除非后续统一修改 Mock 数据定义。
5. 新增 UI 必须依附空间对象或当前章节，单个信息面不超过一个核心结论和五项短数据。
6. 外部资产必须有明确许可证并记录到 `ASSETS.md`；运行时不得依赖外网。
7. 视觉地域默认为江南/长三角现代稻作示范区，不混用热带椰林、北方旱作、防风林等冲突景观。
8. 所有新效果必须提供高、中、低性能档的降级策略；降级只能减少细节，不能破坏故事顺序。

## 7. Data and Integration Notes

- 继续使用本地 Mock 数据，不新增后端、数据库、登录或真实无人机接口。
- 为演示事件增加统一的场景事件模型，至少覆盖：事件 ID、章节、模拟时间、对象 ID、状态、指标和进度区间。
- 现有 `irrigationProgress` 可以继续作为总进度，但设备、水路、湿润锋和复测应由显式区间映射得到，避免散落魔法数字。
- 扫描结果使用本地确定性数据或纹理，保证录屏和重复播放一致。
- 新增照片、贴图、HDRI、GLB、音效或图集时同步更新 `ASSETS.md`。

## 8. Edge Cases

1. 用户在自动演示中点击其他章节。
2. 灌溉进行中再次点击播放、复位或返回总览。
3. 用户直接从“基地总览”跳到“恢复验证”。
4. 低性能设备隐藏粒子、人员或次要装饰物。
5. 窗口从 1440×900 缩小到 1024×768，空间标注与右侧面板发生碰撞。
6. `prefers-reduced-motion` 开启时，镜头和擦拭动画缩短但不消失关键状态。
7. 外部资产解码失败或加载明显慢于场景主体。
8. 自由浏览相机进入预设镜头之外的资产背面。

## 9. Out of Scope

- 真实无人机、遥感、IoT、水利或天气接口。
- 精确水动力、作物生长或灌溉工程仿真。
- 夜间、雨天、四季或完整作物生长周期切换。
- 多地块同时告警、告警中心、历史报表和后台 CRUD。
- 语音讲解、演讲者控制模式和录屏模式；这些属于后续改进包。
- 无人机第一视角和实景/长势交互擦拭；本轮只实现恢复验证的自动对比。

## 10. Acceptance Summary

实施完成必须同时通过：

1. 1440×900 完整五段自动演示；
2. 1024×768 五个章节逐段跳转；
3. A02 扫描、设备启动、水路到达、湿润锋、作物恢复和复测的状态一致性验证；
4. 开场总览、A02 俯冲、异常区、泵站渠道和恢复对比五类截图评审；
5. Chrome 控制台 0 errors；
6. `pnpm typecheck`、`pnpm lint`、`pnpm build`；
7. 所有新增外部资产许可证记录完整。

# FieldVision 产品进化改进报告

> 项目: 禾境 FieldVision | 日期: 2026-07-22 | Evolution ID: EV-20260722-01

## 扫描摘要

- **技术栈**: Vite、React、TypeScript、Three.js / React Three Fiber、Zustand
- **产品基线**: 7 个地块、4 类设施、5 段自动演示、无人机扫描、灌溉水流和风险恢复已经形成可运行闭环
- **任务书状态**: `docs/CODEX_TASK_3D_FARMLAND_DEMO.md` 明确要求 60–90 秒电影式、可进入、可观察、可处置的写实农田演示
- **活跃开发区域**: 近期提交集中在英雄场景写实度、镜头、作物、水渠和演示稳定性
- **上次扫描**: 首次扫描
- **发现**: 12 个改进方向，聚合为 5 个改进包

## 核心判断

当前 Demo 已经从“会动的农田模型”进入“可讲完整故事的空间演示”，下一阶段不应继续横向添加后台功能。最大的提升空间是让观众相信四件事：这是一个真实尺度的农业现场；异常判断有证据；处置过程有因果；恢复结果可以被验证。

现有开场截图中，整体构图和金色晨光已经具备宣传片氛围，但强逆光压低了田块、道路和设施的识别度，远景山体与树线仍带有程序化轮廓，画面缺少车辆、人员、杆线、轮迹等现实尺度参照。业务流程虽然完整，但关键判断仍主要依靠 UI 文案和预设数值表达，三维空间本身尚未充分承担“证据展示”的职责。

## 改进包 1：可解释的异常处置闭环 [综合 RICE: 54.0]

**包含改进**:

1. 空间化扫描证据 [RICE: 45.0] — 无人机扫过时，将植被指数、热区边界、采集时间和可信度直接投射到 A02，而不只显示一句“长势下降”。
2. 设备与水路因果链 [RICE: 27.0] — 依次表现泵站启动、闸门开启、主渠水位上升、支渠到水、田间湿润锋推进，每一步都有空间状态和极简遥测回执。
3. 恢复前后验证 [RICE: 36.0] — 在同一机位提供异常前后擦拭对比或短暂残影，并显示复测时间、墒情变化和影响面积收敛。

**证据链**:

- 任务书第 2.2 节将“发现异常—灌溉处置—恢复验证”定义为演示主体。
- `src/hooks/useDemoSequence.ts` 已具备从扫描、灌溉到恢复的状态链，但扫描与恢复证据目前由固定等待和数值插值驱动。
- `src/ui/FieldDetailPanel.tsx` 已显示 18% → 27% 和长势指数变化，说明数据表达基础已存在，但证据仍主要停留在浮层。
- `src/scene/IrrigationNetwork.tsx` 已有主渠、支渠水面与进度动画，可自然扩展为分段遥测和水位反馈。
- 置信度: High（任务书、状态链、UI 和三维水路四个信号一致）

**建议 PRD 方向**:

把 A02 的处置做成一条可复述的证据链：系统看见了什么、为何判断缺水、发出了什么动作、水到哪里了、如何确认恢复。所有信息仍依附于空间对象，不扩展成独立 Dashboard。

**下一步**:

→ `/prd-generator "为 FieldVision 实现可解释的异常处置闭环，包括空间化扫描证据、设备与水路因果链、恢复前后验证"`

## 改进包 2：导演化现场讲解 [综合 RICE: 38.9]

**包含改进**:

1. 60 秒 / 90 秒双节奏 [RICE: 32.4] — 当前完整流程约 33 秒，增加汇报版停顿、环境镜头和讲解留白，同时保留快速预览版。
2. 演讲者控制模式 [RICE: 19.6] — 支持空格暂停/继续、方向键切章节、当前讲解提示和“一键回到安全机位”。
3. 农田声景与关键动作音效 [RICE: 14.7] — 使用低存在感的风、虫鸟、无人机、泵机和水流声增强临场感，并提供默认静音和明显开关。

**证据链**:

- 任务书目标是 60–90 秒现场汇报，现有 `useDemoSequence` 主流程约 33 秒，缺少讲解留白。
- `DemoTimeline` 已支持章节跳转，但播放中不能暂停后续脚本，也没有演讲者快捷控制。
- 当前产品没有音频层，视觉动作缺少重量和空间反馈。
- 置信度: High（目标时长、实现时长和交互入口均可直接验证）

**建议 PRD 方向**:

建立“自动宣传片”和“现场讲解”两种播放语义，共享同一套镜头章节。重点定义章节进入/退出、暂停后的状态一致性、快捷键和声音默认策略。

**下一步**:

→ `/prd-generator "为 FieldVision 实现导演化现场讲解，包括 60/90 秒双节奏、演讲者控制模式和克制的农田声景"`

## 改进包 3：汇报现场可靠性 [综合 RICE: 33.6]

**包含改进**:

1. 一键演示预检与复位 [RICE: 28.0] — 播放前确认资产加载、画质档位、音频状态和当前章节；异常时自动回到稳定总览，不留下半灌溉状态。
2. 展示屏与录屏模式 [RICE: 21.0] — 增加 16:9 安全区、隐藏鼠标/UI 模式、固定高质量录屏参数和演示完成后的循环静帧。

**证据链**:

- README 明确推荐 1440×900 或 1920×1080 现场汇报和录屏。
- 自动演示依赖页面加载后定时开始，资产或设备状态不确定时缺少正式的“已就绪”门槛。
- 当前已有可取消控制器和 `resetDemo`，具备低成本构建可靠复位的基础。
- 置信度: Medium（需求来自明确使用场景，尚无真实会场故障数据）

**建议 PRD 方向**:

把“打开网页就能播”提升为“任何人拿到现场都不容易播坏”。不增加管理页面，只增加演示前状态、演示中安全操作和演示后复位三个薄层能力。

**下一步**:

→ `/prd-generator "为 FieldVision 实现汇报现场可靠性，包括一键预检复位和展示屏录屏模式"`

## 改进包 4：英雄场景真实尺度 2.0 [综合 RICE: 28.8]

**包含改进**:

1. 照片级稻作区远景 [RICE: 24.0] — 替换程序化山体和交叉树片，增加真实树种层次、田野纵深、空气透视和更符合江南稻作区的地平线。
2. 生产痕迹与尺度锚点 [RICE: 18.7] — 增加机耕路轮迹、渠边淤泥、水尺、供电杆线、农用车、远处作业人员和维护标识。
3. A02 英雄资产精修 [RICE: 16.2] — 将泵站、闸门、涵洞、渠口和近景稻株作为重点资产，补足连接关系、磨损、积水、泥水过渡与边缘细节。

**证据链**:

- 当前截图中远景山体轮廓、树冠重复和大面积同质地表仍最容易暴露“程序化 Demo”感。
- `Atmosphere.TreeLine` 使用实例化平面树冠和程序化地平线，视觉上仍可能出现纸片与重复轮廓。
- `CropInstances` 已有真实行距、密度变化、风摆和恢复变色，说明近景作物已有可继续精修的良好基础。
- 已有 Beads 事项 `fv-3vd` 跟踪“替换远景树线与山体为照片级稻作区资产”。
- 置信度: High（截图、代码、任务书质量红线和已建事项一致）

**建议 PRD 方向**:

以开场总览、A02 俯冲路径、渠口与泵站三个机位为验收对象，先建立视觉参考板和尺度表，再选择照片卡、扫描资产或 Blender 资产方案。新增外部资产必须记录许可证。

**下一步**:

→ `/prd-generator "为 FieldVision 实现英雄场景真实尺度 2.0，包括照片级远景、生产痕迹尺度锚点和 A02 英雄资产精修"`

## 改进包 5：无人机第一视角惊艳点 [综合 RICE: 20.2]

**包含改进**:

1. 同步无人机相机画面 [RICE: 16.8] — 扫描章节短暂切入无人机云台视角，保留小地图式空间上下文，形成“从基地到传感器”的尺度跃迁。
2. 实景 / 长势擦拭镜头 [RICE: 14.9] — 在同一摄影机上用拖动或自动擦拭展示自然色与长势图层差异，避免全场突然换色。
3. 航线与采集点回放 [RICE: 12.6] — 以克制的轨迹、时间戳和三个样点构成一次真实巡检，而不是持续发光的装饰航线。

**证据链**:

- 产品核心卖点包含无人机巡检和长势分析，但目前观众主要从第三人称看到无人机和扫描光锥。
- `Drone`、`RiskOverlay` 与 `LayerSwitcher` 已分别具备飞行、风险区和图层基础，新增视角可复用现有状态。
- 任务书要求观众感知从高空进入具体空间，此包进一步把空间叙事推进到传感器视角。
- 置信度: Medium（技术基础明确，惊艳效果仍需用原型验证）

**建议 PRD 方向**:

先做 8–12 秒可丢弃原型验证眩晕、画面信息量和切镜节奏；若效果成立，再将其嵌入“发现异常”章节，不把无人机画面扩展成新的控制台。

**下一步**:

→ `/prototype "验证 FieldVision 无人机第一视角、实景/长势擦拭和航线采集点回放的 10 秒镜头"`

## 低优先级改进（暂不建议进入下一轮）

| 改进方向 | 原因 |
|---|---|
| 夜间 / 雨天 / 四季切换 | 漂亮但会分散当前异常处置主线，且新增资产与材质状态成本高 |
| 完整 GIS、后台 CRUD、历史报表 | 偏离“三维场景就是产品”的定位 |
| 多地块同时告警 | 会削弱 A02 英雄故事的注意力和因果清晰度 |
| 精确水动力仿真 | 当前目标是可信的演示反馈，不是工程计算产品 |
| 全程大量 HUD 数据 | 会重新滑向传统农业大屏，降低空间沉浸感 |

## 推荐顺序

1. **先做可解释的异常处置闭环**：它直接决定观众是否相信产品，而不只是觉得画面好看。
2. **并行推进英雄场景真实尺度 2.0**：优先完成已存在的 `fv-3vd`，解决最显眼的程序化远景。
3. **随后做导演化现场讲解与可靠复位**：让成果真正适合汇报、录屏和反复演示。
4. **最后用短原型验证无人机第一视角**：成立则作为记忆点，不成立可以低成本放弃。

# 3D 农田数字孪生演示 Demo 开发说明书

> 文件用途：直接交给 Codex 作为项目开发任务书。  
> 项目性质：视觉驱动、可交互、可用于现场汇报的浏览器端三维 Demo。  
> 核心目标：让观众在 60–90 秒内直观感受到“农田可以像三维场馆选座一样被浏览、进入、观察和操作”。

---

## 0. 给 Codex 的执行指令

请根据本说明书创建一个完整、可运行的前端项目。

执行原则：

1. 先阅读完整文档，再制定实现计划。
2. 默认从空目录创建项目。
3. 使用 TypeScript，禁止使用 `any` 逃避类型设计。
4. 优先保证视觉效果、镜头体验和交互完整，不要扩展后台管理功能。
5. 所有数据使用本地 mock 数据，不开发后端、登录、权限、数据库和接口管理页面。
6. 第一轮完成后必须自行运行：
   - 类型检查；
   - ESLint；
   - 生产构建；
   - 基础交互检查。
7. 在 `README.md` 中写清楚启动方法、功能说明、目录结构和可调整参数。
8. 若某个效果实现成本过高，应采用视觉近似方案，不得因为追求真实模拟而阻塞整体交付。
9. 不要把项目做成传统 GIS 大屏或数据 Dashboard。三维农田场景必须占据视觉中心。
10. **逼真度是一级交付目标。禁止使用粗糙低模、纯色几何体、示意性方块或课程示例级模型冒充最终效果。**
11. 镜头近距离可见的作物、地面、渠道、设施、无人机和环境必须具有可信的结构、比例、材质、纹理、阴影与细节。
12. 在性能与画质冲突时，应采用 LOD、实例化、贴图烘焙和分级加载优化，不得首先通过把核心模型做粗糙来解决。
13. 项目最终应做到：打开页面即可自动开始一段电影式三维演示，同时允许用户自由操作。

## 0.1 最高优先级质量红线：必须尽可能逼真

本 Demo 的目标不是快速拼出“能转动的三维农田示意图”，而是制作一个在浏览器中具有较高真实感、能够用于正式汇报和录屏展示的三维场景。

目标观感应接近：

- 高质量农业数字孪生宣传片；
- 写实风格的实时游戏环境；
- 高端产品官网中的交互式 3D 场景；
- 无人机低空航拍与地面实景相结合的视觉体验。

最低要求：

1. **近景经得起观察。** 镜头进入 A02 地块后，前景作物、泥土、田埂、水面和渠道不能暴露明显的纸片感、塑料感、重复纹理或低面数轮廓。
2. **比例可信。** 作物高度、行距、渠道宽度、道路尺度、设备体量、无人机大小和相机高度必须符合现实直觉。
3. **材质可信。** 使用 PBR 材质体系，至少合理处理 base color、roughness、normal；关键资产视情况增加 ambient occlusion、metalness、displacement 或 height。
4. **环境可信。** 地形不能像平板；边缘不能过于规整；作物分布不能完全机械重复；道路、泥土和水渠应有自然过渡、污渍、湿润差异和细节变化。
5. **光照可信。** 使用高质量天空环境、太阳方向光、软阴影、环境遮蔽、色调映射和适度雾效，避免“模型查看器”式平光。
6. **运动可信。** 作物风摆、无人机飞行、水流、镜头运动和设备启动都应具有重量感与惯性，不得机械匀速或突然启停。
7. **禁止以占位资产作为最终交付。** 开发早期可以使用占位体，但最终验收前必须替换核心可见资产。
8. **优先打磨英雄区域。** 不要求整个基地每个角落都达到同等精度，但开场总览、A02 飞入路径、A02 地面视角、泵站、东支渠和无人机巡检路径必须达到最高精度。

推荐采用“分层真实感”策略：

```text
镜头 0–20 米：高精度模型 + 高质量 PBR 材质 + 丰富细节
镜头 20–80 米：中等精度模型 + 实例化 + 简化阴影
镜头 80 米以上：低精度 LOD、合批、纹理或轮廓表达
```

视觉评审时，必须同时检查：

- 开场高空总览截图；
- A02 俯冲过程截图；
- 作物高度近景截图；
- 泵站和水渠近景截图；
- 无人机扫描截图；
- 灌溉恢复前后对比截图。

# 1. 项目定义

## 1.1 项目名称

中文名称：

**稻田之眼 · 3D 农田数字孪生**

英文副标题：

**FieldVision — Interactive 3D Farmland Twin**

代码仓库建议名称：

```text
fieldvision-3d-demo
```

## 1.2 一句话定位

一个可以从高空俯瞰农场、点击进入具体地块、查看作物长势，并动态演示灌溉与风险处置过程的三维数字农田 Demo。

## 1.3 与普通农田管理系统的区别

本项目不是：

- 普通二维地图；
- 农业数据大屏；
- 表格和卡片堆砌的管理后台；
- 完整农业生产 SaaS；
- 精确的真实物理或水利仿真系统。

本项目要展示的是：

> 农田不再只是地图上的一个色块，而是一个可以进入、观察、操作、推演和验证的三维空间。

# 2. 演示目标

## 2.1 最终观众感受

现场观众看到 Demo 后，应产生以下感受：

1. 农田空间非常直观，可以像浏览游戏地图一样浏览整个基地。
2. 点击任意地块，镜头能够平滑进入地块内部，而不是只弹出一个信息框。
3. 作物长势、灌溉路径、异常区域和设备状态能直接呈现在三维空间中。
4. 系统不仅能发现问题，还能通过一个动态过程展示“问题如何被处理”。
5. 该方案具有继续扩展到遥感、无人机、物联网、生产管理和高标准农田管护的潜力。

## 2.2 90 秒推荐演示路径

完整演示应支持以下讲解节奏：

### 第 1 段：基地亮相，约 15 秒

页面打开后，镜头从云层上方缓慢下降，展示完整农田基地：

- 多块不规则农田；
- 田间道路；
- 主灌溉渠和支渠；
- 泵站、闸门、气象站；
- 作物随风轻微摆动；
- 一架无人机沿预设航线巡航；
- 远处有雾、山丘或树线；
- 画面具有日出或清晨的电影感。

### 第 2 段：进入具体地块，约 20 秒

镜头锁定 A02 地块：

- 地块边缘出现高亮描边；
- 地块标签悬浮出现；
- 镜头从高空俯冲至地块上方；
- 继续下沉至接近作物高度；
- 用户能看到成排作物、田埂、水渠和远处设施；
- 右侧出现半透明地块信息面板。

这一步是整个 Demo 对标“三维场馆选座案例”的核心体验：

> 点击一个空间对象，镜头真正进入那个位置，让用户看到“置身其中会是什么感觉”。

### 第 3 段：发现异常，约 20 秒

切换“长势分析”图层：

- A02 局部区域从绿色渐变为黄色、橙色；
- 异常区域出现轻微脉冲；
- 无人机飞至异常区域上空；
- 无人机下方出现扫描光锥或扫描网格；
- UI 提示：长势指数下降、土壤墒情偏低；
- 镜头短暂环绕异常区域。

### 第 4 段：灌溉处置，约 20 秒

点击“启动灌溉演示”：

- 镜头转向泵站；
- 泵站状态灯由灰色变为绿色；
- 水流沿主渠、支渠向 A02 流动；
- 水渠中出现清晰的流动动画；
- A02 地块内部出现灌溉扩散效果；
- 异常区域颜色逐步由橙色恢复为绿色；
- 墒情数字从 18% 动画增长至 27%。

### 第 5 段：闭环完成，约 15 秒

镜头重新拉升到基地总览：

- A02 风险标记消失；
- 顶部状态显示“风险已解除”；
- UI 显示“影响面积 180 亩，处置完成”；
- 无人机继续巡航；
- 整个农场恢复平静、稳定的视觉状态。

# 3. 产品范围

## 3.1 必须实现

### 三维场景

- 一个完整的三维农田基地；
- 6–8 块形状不同的地块；
- 起伏轻微的地形；
- 农田周边环境；
- 主渠、支渠和田间道路；
- 至少三类设施；
- 至少两种作物视觉差异；
- 一架动态巡航无人机。

### 镜头能力

- 自动开场镜头；
- 高空基地总览；
- 点击地块后平滑飞入；
- 接近作物高度的沉浸视角；
- 环绕地块或异常区域；
- 一键返回总览；
- 演示模式和自由浏览模式切换。

### 空间交互

- 鼠标悬停地块高亮；
- 点击地块选中；
- 点击设施显示名称和状态；
- 地块标签始终面向相机；
- 异常区域具有脉冲或动态边缘；
- UI 操作能直接驱动三维场景变化。

### 动态演示

- 无人机自动巡航；
- 无人机扫描效果；
- 灌溉水流动画；
- 地块长势颜色变化；
- 风险状态从异常变为正常；
- 数值变化与三维动画同步。

### UI

- 顶部极简状态栏；
- 左下角图层切换；
- 右侧地块详情面板；
- 底部演示步骤或时间线；
- 一个“播放完整演示”按钮；
- 一个“启动灌溉演示”按钮；
- 一个“返回基地总览”按钮。

## 3.2 可以实现，但不是第一优先级

- 白天 / 夜晚切换；
- 雨天效果；
- 季节切换；
- 作物从播种到成熟的生长动画；
- 真实卫星底图；
- 视频录制；
- 语音讲解；
- 移动端完整交互。

## 3.3 明确不做

- 用户登录；
- 权限系统；
- 数据库；
- 后端 API；
- 真实遥感数据处理；
- 真实水动力计算；
- 真实 GIS 坐标投影；
- 完整农业生产计划；
- 表格 CRUD；
- 消息中心；
- 报表系统；
- 多租户；
- 设备接入协议；
- 精确 BIM 或工程模型。

# 4. 视觉设计要求

## 4.1 总体风格

关键词：

```text
cinematic
premium
immersive
clean
futuristic agriculture
real-time digital twin
photorealistic real-time farmland
```

中文理解：

- 电影式；
- 高级；
- 沉浸；
- 克制；
- 有科技感但不是赛博朋克；
- 以尽可能逼真的实时写实效果为目标，而不是低模或示意风；
- 核心镜头应接近高质量写实游戏场景、数字孪生宣传片或高端产品官网 3D 展示；
- 浏览器性能允许的范围内，优先提升模型、纹理、植被、光照和环境细节；
- 避免传统政务大屏风格。

## 4.2 色彩

场景基础色：

- 土地：深褐、暖灰褐；
- 正常作物：深浅不同的自然绿色；
- 水渠：偏青蓝但不能荧光过度；
- 道路：低饱和米灰；
- 建筑和设备：深灰、银灰；
- 天空：清晨蓝灰与暖色日光。

状态色：

- 正常：自然绿色；
- 关注：黄色；
- 异常：橙红；
- 正在处理：青蓝；
- 已完成：高亮绿色。

UI：

- 深色半透明玻璃；
- 白色主文字；
- 低饱和灰色辅助文字；
- 少量青绿色高亮；
- 不使用大面积高饱和渐变。

## 4.3 光照与氛围

必须实现：

- 柔和环境光；
- 有明确方向的太阳光；
- 实时阴影；
- 轻微雾效；
- 颜色映射和曝光控制；
- 地面接触阴影；
- 远景层次。

推荐效果：

- 清晨斜射光；
- 作物和树木具有细微风动；
- 水面有高光；
- 天空云层缓慢移动；
- Bloom 只能用于状态灯、水流高光和扫描效果，不能让整个画面发光。

## 4.4 视觉禁忌

禁止：

- 纯色方块拼成的低质量农田；
- 使用简单 Box、Cylinder、Plane 拼出的设施作为最终模型；
- 将交叉纸片植被直接暴露在核心近景中；
- 使用无 Normal、Roughness 变化的塑料感材质；
- 地面只铺一张重复明显的平面贴图；
- 所有作物高度、朝向、颜色和间距完全相同；
- 水面像蓝色玻璃板，没有流动、深浅和岸边过渡；
- 山体、树木、设备和无人机出现明显低多边形轮廓；
- 大量霓虹线框；
- 蓝色科技光效覆盖全部画面；
- 过度 Bloom；
- 过多浮动数据标签；
- 传统大屏边框装饰；
- 满屏 KPI 卡片；
- 镜头瞬移；
- 卡通农场风；
- Minecraft 式方块风；
- 页面加载后停留在静态总览。

## 4.5 写实资产与材质标准

### 核心资产策略

最终展示中，以下对象必须使用经过打磨的模型或高质量程序化模型，不得使用粗糙占位体：

- 无人机；
- 泵站及其管线；
- 灌溉闸门；
- 气象站；
- 管理站或仓房；
- 近景树木和灌木；
- A02 地块近景作物；
- 田埂、渠道和进水口。

允许使用开源或许可清晰的 GLTF / GLB 资产和 PBR 贴图，但必须：

1. 确认许可证允许项目使用；
2. 将资产来源和许可证记录在 README；
3. 统一比例、坐标轴、材质和色调；
4. 对过大的贴图和网格进行压缩与优化；
5. 禁止把风格不一致的素材直接拼接到场景中。

### 模型质量

核心近景模型要求：

- 轮廓自然，关键结构完整；
- 合理倒角，避免所有边缘像刀片一样锐利；
- 法线正确；
- UV 不明显拉伸；
- 关键部件具有局部细节；
- 设备尺寸符合农业场景尺度；
- 无悬空、穿插和明显接缝。

不要求无限增加面数。应把几何细节投入到：

- 轮廓；
- 近景结构；
- 会产生阴影的部分；
- 会被镜头特写的部分。

细碎表面细节优先通过 Normal、Roughness、AO 和 Decal 表达。

### 纹理质量

英雄区域推荐使用 2K 纹理；极近景核心资产可使用 4K，但必须控制数量。中远景可使用 1K 或图集。

地面至少区分：

- 干燥土壤；
- 湿润土壤；
- 田埂压实土；
- 道路；
- 渠岸；
- 水边泥泞区域。

需要通过纹理混合、顶点色、噪声遮罩或 Decal 消除规则边界和明显重复。

### 植被质量

作物是本 Demo 是否逼真的关键。

A02 地块近景要求：

- 前景作物应使用具备真实轮廓的低中面数模型或高质量卡片组；
- 叶片宽窄、弯曲、倾斜和颜色具有变化；
- 根部与地面自然衔接；
- 行列分布符合种植规律，但存在轻微自然扰动；
- 不同距离采用至少 2–3 级 LOD；
- 风动应体现叶片顶部摆动，根部基本稳定；
- 相机近距离时不能明显看出所有植株完全相同。

中远景可以使用实例化、Billboard、纹理簇或密度简化，但视觉切换不能明显跳变。

### 水体质量

水渠和灌溉水体至少应具有：

- 水面法线变化；
- 天空和环境反射；
- 深浅或浑浊度差异；
- 岸边湿润过渡；
- 流向可感知；
- 闸门附近的局部扰动；
- 灌溉启动前后明显不同的动态状态。

不要求真实流体求解，但视觉上必须像水，而不是移动的蓝色光带。

### 环境质量

背景环境必须帮助建立真实尺度：

- 远处树线应有层次；
- 山丘或地平线不能像简单三角形；
- 天空与太阳方向一致；
- 雾只用于空气透视，不能遮盖粗糙模型；
- 场景中加入适量细节，如杂草、车辙、石块、沟渠污渍、设备铭牌或警示条；
- 细节应集中在镜头经过区域，避免平均铺设造成性能浪费。

# 5. 三维场景设计

## 5.1 场景空间构成

建议使用一个虚拟基地，不需要真实地理坐标。

基地范围可设为：

```text
宽约 320 个场景单位
长约 240 个场景单位
高度变化 0–8 个场景单位
```

场景包含：

1. 6–8 块不规则地块；
2. 一条贯穿基地的主灌溉渠；
3. 两到三条支渠；
4. 一条主道路和若干田间道路；
5. 一个泵站；
6. 两个闸门；
7. 一个气象站；
8. 一个小型仓房或管理站；
9. 若干树木、灌木、田埂和电线杆；
10. 远处低山、树线或雾化背景。

## 5.2 地块规划

建议使用以下 mock 地块：

| ID | 名称 | 面积 | 作物 | 状态 |
|---|---|---:|---|---|
| A01 | 西区一号田 | 220 亩 | 水稻 | 正常 |
| A02 | 东区二号田 | 180 亩 | 水稻 | 墒情异常 |
| A03 | 北区三号田 | 260 亩 | 玉米 | 正常 |
| B01 | 西南一号田 | 190 亩 | 水稻 | 正常 |
| B02 | 中区二号田 | 160 亩 | 蔬菜 | 正在灌溉 |
| B03 | 东南三号田 | 270 亩 | 油菜 | 设施影响 |
| C01 | 试验田 | 85 亩 | 水稻 | 试验中 |

所有地块必须：

- 使用不规则多边形；
- 具有细微高程差；
- 具有清晰田埂；
- 能够被射线检测；
- 能够单独高亮；
- 能够切换状态材质；
- 能够关联镜头预设点。

## 5.3 作物表现

### 水稻

使用 `InstancedMesh` 渲染大量经过优化、但具有可信轮廓和材质的稻株。

要求：

- 核心近景不得仅使用两张明显交叉的平面；应使用低中面数叶片模型、高质量多卡片簇，或近景模型与中远景卡片混合方案；
- 高度和旋转有随机扰动；
- 颜色有少量随机差异；
- 使用简单顶点动画模拟风摆；
- 密度随距离使用 LOD 或采样降低。

### 玉米

- 数量少于水稻；
- 单株更高；
- 使用低面数茎秆和叶片；
- 行列感更明显。

### 其他作物

蔬菜和油菜可以采用简化植被簇，不需要复杂模型。

## 5.4 地形

建议：

- 使用细分平面；
- 通过确定性噪声生成轻微起伏；
- 农田区域整体较平；
- 周边地形可以更高；
- 不需要真实 DEM；
- 地形不能遮挡主要地块。

## 5.5 水渠

水渠需要同时承担空间表达和演示动画。

构成：

- 凹陷渠槽；
- 水面；
- 渠岸；
- 闸门；
- 水流方向标识。

水流动画可选方案：

1. 沿曲线移动的发光粒子；
2. 沿曲线滚动的纹理；
3. Shader 中改变 UV 偏移；
4. 半透明水面上叠加方向性高光。

优先选择稳定、易控制、可清楚表达“水正在流动”的方案，不要求真实流体。

# 6. 核心交互设计

## 6.1 开场自动演示

页面资源加载完成后：

1. 显示简洁加载界面；
2. 加载完成后淡出；
3. 相机从云层或远处开始；
4. 缓慢飞向基地；
5. 绕基地约 20–30 度；
6. 停在最佳总览角度；
7. 显示基地名称和核心指标；
8. 自动进入可交互状态。

开场总时长建议：

```text
6–9 秒
```

必须提供“跳过开场”。

## 6.2 悬停地块

鼠标悬停时：

- 地块边缘发亮；
- 作物亮度轻微提升；
- 出现浮动标签；
- 光标变为可点击；
- 不弹出大型信息面板。

## 6.3 点击进入地块

点击 A02 后执行：

1. 锁定当前地块；
2. 显示地块高亮边缘；
3. 隐藏无关标签；
4. 相机先略微抬升；
5. 沿弧线路径飞向地块；
6. 降低到作物上方；
7. 最后进入接近人眼高度的地块视角；
8. 相机看向作物、渠道或异常区域；
9. 打开右侧详情面板。

镜头动画必须：

- 使用 easing；
- 不发生突然旋转；
- 不穿过地形和作物；
- 时长约 1.8–2.8 秒；
- 支持用户中途打断。

## 6.4 地块沉浸视角

这是核心亮点。

相机高度建议：

```text
1.8–3.5 个场景单位
```

画面中应同时看到：

- 前景作物；
- 中景田埂或水渠；
- 远景设施、树线和天空；
- 少量 UI；
- 轻微景深效果。

可增加“视角切换”：

- 鸟瞰；
- 田边；
- 作物高度；
- 灌溉口。

## 6.5 图层切换

支持以下图层：

### 实景模式

自然材质和正常农业场景。

### 长势模式

不同地块或局部网格按长势状态着色：

- 绿色：良好；
- 黄色：关注；
- 橙色：异常。

### 墒情模式

以半透明热力层叠加在地块上。

### 设施模式

弱化作物和环境，突出：

- 泵站；
- 闸门；
- 水渠；
- 气象站；
- 设备连接关系。

图层切换需要平滑过渡，不允许瞬间闪烁。

## 6.6 无人机巡检

无人机行为：

- 默认沿预设三维曲线路径循环飞行；
- 机身朝向运动方向；
- 螺旋桨旋转；
- 有轻微上下浮动；
- 经过异常地块时降低高度；
- 进入扫描状态时显示扫描光锥或网格。

点击无人机可：

- 让镜头跟随无人机；
- 显示“巡检中”状态；
- 再次点击退出跟随。

## 6.7 灌溉演示

点击“启动灌溉演示”后：

### 阶段 1：设施启动

- 泵站状态灯点亮；
- 泵站产生轻微机械振动或光环；
- UI 显示“泵站已启动”。

### 阶段 2：主渠进水

- 水流从泵站进入主渠；
- 流动方向清晰；
- 相机可短暂跟随水流。

### 阶段 3：支渠分配

- 对应闸门开启；
- 水流转入 A02 支渠；
- 未使用支渠保持静止。

### 阶段 4：地块灌溉

- A02 内部出现从进水口向外扩散的湿润区域；
- 墒情数值从 18% 逐渐变为 27%；
- 异常热力颜色逐渐回归绿色。

### 阶段 5：完成

- 风险脉冲停止；
- 状态更新为“已恢复”；
- UI 显示处置完成；
- 镜头回到较高视角展示结果。

总时长建议：

```text
12–18 秒
```

# 8. 推荐技术方案

## 8.1 技术栈

建议使用：

```text
Vite
React
TypeScript
Three.js
@react-three/fiber
@react-three/drei
@react-three/postprocessing
Zustand
Tailwind CSS
Lucide React
```

可选：

```text
GSAP
leva
```

说明：

- `@react-three/fiber` 用于将 Three.js 场景组件化；
- `@react-three/drei` 用于相机控制、HTML 标签、环境、性能辅助等；
- `@react-three/postprocessing` 用于 Bloom、景深、暗角等后期效果；
- Zustand 用于集中管理场景状态和演示步骤；
- GSAP 只在普通 UI 动画或复杂时间线确实更方便时引入；
- `leva` 只允许用于开发调参，生产页面默认隐藏。

## 8.2 为什么不使用 Cesium 或 MapLibre

当前 Demo 目标是高质量自定义三维体验，而不是：

- 大范围真实地理数据；
- 在线地图瓦片；
- 精确坐标定位；
- 真实地球尺度；
- GIS 图层管理。

因此第一版不要引入 Cesium、MapLibre 或复杂 GIS 依赖。

## 8.3 渲染设置

建议：

- 使用 WebGLRenderer；
- 开启抗锯齿；
- 开启透明背景仅在确有需要时；
- 使用 ACES Filmic Tone Mapping；
- 调整合理曝光；
- 开启阴影；
- 阴影只给关键物体；
- DPR 根据设备性能动态限制；
- 使用性能分级。

## 8.4 后期效果

建议组合：

- 轻量 Bloom；
- SSAO 或类似环境遮蔽；
- 轻微 Vignette；
- 选中物体 Outline；
- 地块沉浸视角时使用轻微 Depth of Field；
- 不要同时堆叠过多 Pass。

## 8.5 写实资产管线

建议建立明确的资产处理流程：

```text
获取或制作资产
→ 检查许可证
→ Blender 中统一尺度与朝向
→ 清理网格和材质
→ 生成 LOD
→ 合并或图集化贴图
→ Draco / Meshopt 压缩
→ KTX2 / Basis 纹理压缩
→ 导出 GLB
→ 浏览器实机检查
```

核心资产加载要求：

- 使用 GLB / GLTF；
- 按开场必需、近景必需、延迟加载三组拆分；
- 开场前只阻塞加载第一镜头必需资源；
- A02 高精度作物和设施可在开场播放期间预加载；
- 使用低精度代理避免资源未完成时画面空缺；
- 高精度资源加载完成后平滑替换，不能明显闪变。

如项目环境允许，可使用 Blender 脚本辅助：

- 批量缩放；
- 原点归一；
- 材质命名；
- LOD 生成；
- GLB 导出；
- 贴图尺寸检查。

# 12. 场景实现建议

## 12.1 地块几何

每块地：

1. 使用二维多边形坐标；
2. 转换为 Three.js `Shape`；
3. 生成轻微厚度的 `ExtrudeGeometry`；
4. 表面承载作物；
5. 边缘使用独立 Line 或描边 Mesh；
6. 鼠标事件绑定到透明或低复杂度拾取 Mesh；
7. 视觉 Mesh 与拾取 Mesh 分离，避免复杂实例影响射线检测。

## 12.2 作物实例

使用 `InstancedMesh`：

- 通过 seeded random 保证每次刷新布局一致；
- 仅在多边形内部生成；
- 排除田埂、水渠和设施区域；
- 距离相机越远，实例越稀疏；
- 远距离可以切换为纹理、低密度点或简化颜色面。

## 12.3 风动

使用简单 Shader 或每帧更新：

- 根部基本固定；
- 顶部随时间和世界坐标摆动；
- 不同地块风相位不同；
- 幅度必须克制；
- 性能不足时关闭。

## 12.4 地块状态材质

不要直接替换整块地的纯色。

建议：

- 正常模式保留自然材质；
- 风险模式在上方叠加半透明 Mesh；
- 使用渐变和噪声打散边缘；
- 风险区域有缓慢脉冲；
- 处置时通过统一进度值驱动颜色恢复。

## 12.5 相机控制

建议建立 `CameraDirector`：

职责：

- 接收业务状态；
- 执行预设镜头；
- 在自动演示和自由控制之间切换；
- 支持中断；
- 处理返回总览；
- 控制景深焦点。

镜头运动不能散落在多个组件中。

## 12.6 演示时间线

建立单独的演示序列配置：

```ts
interface DemoCue {
  id: DemoStep;
  delayMs: number;
  durationMs: number;
  cameraPreset?: string;
  layerMode?: LayerMode;
  selectedFieldId?: string;
  narration?: string;
  onEnter?: string;
}
```

不要使用大量嵌套 `setTimeout`。

可以使用：

- 一个统一的 async sequence；
- 可取消 Promise；
- GSAP Timeline；
- 或明确的状态机。

必须支持：

- 播放；
- 暂停；
- 跳转；
- 重置；
- 用户操作中断。

- 环境声可选；
- 指标延迟出现。

## 13.2 选中地块

动画顺序：

```text
hover 高亮
→ click
→ 边界描边增强
→ 标签变为选中状态
→ 镜头飞入
→ 右侧面板出现
```

## 13.3 风险扫描

动画顺序：

```text
无人机偏航
→ 加速飞向 A02
→ 悬停
→ 扫描锥出现
→ 地表网格被扫描
→ 风险热区逐渐显现
→ UI 显示分析结果
```

## 13.4 灌溉

需要至少三种同步变化：

1. 水渠流动；
2. 地块颜色恢复；
3. UI 数字增长。

三者必须共享同一个 `irrigationProgress`，避免动画不同步。

# 14. 性能要求

## 14.1 目标

性能优化的原则是“保持英雄镜头的真实感，再优化不可见或远距离内容”，不得以全场景低模化作为首选方案。

桌面端：

- 目标 60 FPS；
- 普通集成显卡不低于 30 FPS；
- 首次有效画面尽量控制在 3 秒左右；
- 完整资源加载尽量控制在 8 秒内。

移动端：

- 可以降低植被密度；
- 关闭景深和高成本环境遮蔽；
- DPR 最大限制为 1.5；
- 目标 30 FPS。

## 14.2 必须采用的优化

- `InstancedMesh`；
- 植被距离裁剪；
- DPR 限制；
- 阴影对象白名单；
- 避免每帧创建对象；
- 复用 Geometry 和 Material；
- 使用 `useMemo`；
- 将静态对象设为不频繁更新；
- 减少透明材质叠加；
- 限制后期处理数量；
- 预加载必要资源；
- 对低性能设备降级。

## 14.3 性能分级

建议：

```ts
type PerformanceTier = "low" | "medium" | "high";
```

高：

- 全植被；
- 阴影；
- SSAO；
- 景深；
- 高 DPR。

中：

- 降低植被；
- 保留阴影和 Bloom；
- 关闭景深。

低：

- 大幅降低植被；
- 简化水面；
- 关闭 SSAO、景深和动态环境；
- DPR 设为 1。

# 17. 验收标准

## 17.1 核心验收

以下项目全部满足才算完成：

- [ ] 页面打开后自动播放电影式三维开场；
- [ ] 三维场景是视觉主体；
- [ ] 至少有 6 块可独立交互的不规则地块；
- [ ] 地块中存在可感知的作物；
- [ ] 点击地块后相机平滑飞入；
- [ ] 能进入接近作物高度的沉浸视角；
- [ ] 有一架持续巡航的无人机；
- [ ] 无人机能对异常区域进行扫描；
- [ ] 支持自然、长势、墒情和设施四种视图；
- [ ] A02 有明确的风险区域；
- [ ] 点击按钮能播放完整灌溉处置动画；
- [ ] 水流、地块状态和 UI 数值同步变化；
- [ ] 演示完成后风险从异常变为正常；
- [ ] 支持返回总览；
- [ ] 支持完整演示重播；
- [ ] 生产构建无错误；
- [ ] 无明显控制台错误；
- [ ] MacBook Chrome 或 Safari 上运行流畅。

## 17.2 视觉验收

- [ ] 不像传统管理后台；
- [ ] 不像二维 GIS 大屏；
- [ ] 不像简单课程示例；
- [ ] 镜头运动具有电影感；
- [ ] 画面有前景、中景和远景；
- [ ] 光照和雾效形成空间层次；
- [ ] UI 克制且不遮挡主体；
- [ ] 异常效果醒目但不过度；
- [ ] Bloom 没有污染整个画面；
- [ ] 作物没有明显机械重复感；
- [ ] A02 作物高度近景没有明显纸片感和低模轮廓；
- [ ] 泵站、闸门、无人机等核心资产不是基础几何体占位；
- [ ] 地面具有泥土、湿润、车辙或田埂等可辨识细节；
- [ ] 材质具有合理的粗糙度、法线和光照响应；
- [ ] 水渠在静止和流动状态下均具有可信水体观感；
- [ ] 核心截图在 100% 尺寸查看时没有明显粗糙、穿模和纹理拉伸。

## 17.3 失败判定

出现以下任意情况，应视为未达到目标：

- 点击地块只弹出卡片，镜头不进入；
- 场景主体是 2D 地图；
- 农田仅由几块矩形平面组成；
- 核心近景仍使用低模占位体、纯色几何体或明显交叉纸片；
- 无人机、泵站、闸门等资产呈现课程示例级粗糙感；
- 作物、地面、水渠在近距离观察时明显失真；
- 无人机只是静态模型；
- 水流只是文字提示；
- 长势恢复只更新数字，不更新场景；
- 镜头大量瞬移；
- 页面一打开是 KPI 大屏；
- 为了真实模拟而导致演示无法顺畅运行；
- 实现大量非必要业务功能，核心视觉仍未完成。

# 22. 最终效果判断

这个项目成功与否，不取决于功能数量，而取决于以下瞬间是否足够有冲击力：

> 用户从高空看到完整基地，点击 A02 地块，镜头像进入三维场馆座位一样快速而平滑地俯冲到稻田内部。作物在前景随风摆动，无人机从头顶飞过，异常区域在田间亮起。随后水流从泵站沿渠道进入地块，橙色风险区域逐渐恢复为绿色。

只要这一段在镜头、模型、材质、光照和动画上都具有足够真实感，Demo 才成立。核心效果不能停留在低模原型或粗糙技术验证层面。

反之，即使增加很多指标、表格和管理功能，只要缺少这一段沉浸式空间体验，Demo 就没有达到目标。
